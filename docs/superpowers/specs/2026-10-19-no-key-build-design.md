# Remaining phases with no API keys

## User intent

Finish the original multi-tenant knowledge base plan sequentially with specialist subagents and a passing full unit suite between phases. User has no API keys. Preserve working Phase 1 and provide a useful local demo plus optional live integrations. The prior GitHub push authorization persists.

## Controller implementation choices

- `demo_mode=True` by default. Missing live credentials never cause local startup to fail. Demo ConnectWise reads synthetic fixtures; live mode validates needed settings when invoked. No silent fallback on live integration failures.
- `draft_provider='local'` defaults to deterministic extraction/classification with explicit documentation that it is not an LLM. Optional `ollama` supports actual local LLM drafting with no API key, using an already installed user-selected model; optional `openai` uses Pydantic structured output from sanitized text. No cloud calls or model downloads in local defaults/tests.
- Qdrant embedded storage defaults to a local ignored directory, requiring no server/key. `embedding_provider='hash'` provides deterministic local lexical feature hashing for the zero-download demo; optional `fastembed` uses a genuine FastEmbed model and requires a first-use model download. A given collection must not mix embedding providers/models/dimensions; reject mismatches. Optional remote Qdrant honors configured URL/key.
- PII sanitization is applied before drafting and again before indexing/query embedding. Rules cannot guarantee all sensitive information is detected; document the limitations. Original raw tickets remain in SQLite. Redaction tokens do not downgrade tenant-specific content to global: classify sensitivity from original context locally before scrubbing and enforce tenant scope after LLM output.
- Demo is explicitly local development. Use a configurable management bearer token and a separate webhook shared secret for live mode; deny access to protected live routes when their secret is unconfigured. Do not present client-supplied tenant IDs as user authorization. Retrieval contract filters global plus the supplied tenant only; user identity/tenant authorization is a separate deployment concern, documented plainly.

## Phase 5 — RAG & Search Engineer

Create `app/vector_db.py` using qdrant-client and optional fastembed. Chunk sanitized approved documents with overlap; deterministic point IDs include article and chunk, payload scope/tenant_id/category/article_id/title/text and embedding signature. Allow approved/indexed drafts only; reindexing replaces stale chunks, unapproved records never searchable, and verify article status against SQL before returning results if needed. Strict Qdrant payload filtering: no tenant -> global AND tenant_id null only; tenant -> these globals OR scope tenant AND exact tenant_id. Reject invalid tenant IDs; always filter before retrieval. `search_knowledge_base(query_str, tenant_id=None)` public callable and settings/app injection must avoid shared tenant/filter state. Indexed status only after vector success; failure remains approved for retry; repeat approvals/indexing idempotent. Qdrant/SQL are not an atomic transaction: document recovery and avoid exposing pending records after partial failures.

Management routes under `/api/v1/kb`: list/get drafts, search, approve pending drafts and index them. Explicit review gate; generating a draft never approves it. Protect live management/search operations as described above. Demo uses same HTTP API without credentials. Provide a runnable `python -m app.demo` command to seed only synthetic tickets/assets/drafts for two tenants and a generic global example; do not automatically approve drafts. Document actual HTTP commands to list/review/approve/search and verify cross-tenant isolation, local versus live choices, credential settings and fallback limitations. Add complete workflow tests with real embedded in-memory Qdrant and local embedding; no model downloads/network. Close Qdrant clients on lifespan shutdown, avoid import-time initialization or model downloads, and ignore local storage/cache outputs.
